# 11. 논리적 설계 심화

> **합치기 / 기록 / 규칙 / 표준**

---

## 1. 개체 통합

비슷한 표 → **하나로**

| 가능 | 뜻 |
|---|---|
| 기본키 같음 | 같은 대상 |
| 서로 식별 | 1:1 |
| 속성 비슷 | 구조 비슷 |

**좋음:** 중복↓, 관리 쉬움, ERD 단순  
**주의:** 의미 흐림, 데이터 몰림

---

## 2. 이력

이력 = **과거 기록**

| 종류 | 예 |
|---|---|
| 발생 | 급여, 접속 |
| 변경 | 예약 변경 |
| 진행 | 접수→면접→선발 |
| 시점 | 환율 |
| 선분 | 기간별 공연 지역 |

필요할 때만 저장.  
보통 `원래PK + 날짜/순번`.

---

## 3. 코드

코드 = **짧은 약속**

예: `1=카드`, `2=현금`

| 종류 | 예 |
|---|---|
| 1개 속성 | 지불방법코드 |
| 여러 속성 | 부서구분코드 |

겹치면 안 됨.  
너무 단순하면 생략: 남/여, 유/무

---

## 4. 무결성

무결성 = **잘못된 값 방지**

| 종류 | 핵심 |
|---|---|
| 개체 | 기본키 |
| 참조 | 외래키 |
| 도메인 | 값 범위 |

### 기본키

중복 X, NULL X, 잘 안 바뀜, 개인정보 X

예: 학생은 `학번`

### 외래키

없는 부모 참조 X

예: 사원 부서번호 → 실제 부서 필요

### 도메인

값의 규칙

예: 점수 0~100, 나이 0 이상, 필수값 NULL X

---

## 5. 데이터 표준화

표준화 = **이름 통일**

예: 고객번호 / 고객ID / 회원번호 → 하나로

| 대상 | 뜻 |
|---|---|
| 단어 | 낱말 |
| 용어 | 업무 이름 |
| 도메인 | 타입/길이/범위 |
| 코드 | 코드값 |

규칙: 한글명은 논리, 영문명은 물리.  
이력은 이름 뒤에 `이력`, 시간은 `일시`.

---

## 6. ERD → 릴레이션

1. 개체 → 테이블
2. 관계 → 테이블
3. 가능하면 합침
4. 최종 스키마
5. PK/FK/도메인

관계 PK ≠ 개체 PK → 함부로 합치지 않기

## 정리..

| 말 | 뜻 |
|---|---|

| 도메인 | 값 범위 |
| 이력 | 과거 |
| 코드 | 약속 |
| 표준화 | 이름 통일 |
