# 12주차 과제: 3NF 정규화

## 1. 대상 릴레이션

- 직원(직원번호, 이름, 연락처, 역할)
- 고객(고객번호, 이름, 주민번호, 연락처, 주소)
- 차량(차량식별번호, 차량번호, 모델명, 연식, 차량상태, 매입가, 판매가, 매물등록일, 판매일, 작업일, 부대비용, 작업명, 정비항목, 진행상태)
- 판매계약(계약번호, 계약일, 계약금액, 판매방식, 인도완료여부, 인도일, 예약일, 예약상태, 차량식별번호, 고객번호, 직원번호)
- 사후처리(처리번호, 처리유형, 요청일, 처리일, 처리내용, 처리상태, 보증기간, 보증항목, 차량식별번호, 고객번호)
- 관리하다(직원번호, 차량식별번호)
- 처리하다(직원번호, 처리번호)

## 2. 정규화 과정

### 1NF

한 칸에는 값이 하나만 있어야 한다.  
차량의 `정비항목`은 여러 개가 될 수 있으므로 분리한다.

- 차량작업(작업번호, 차량식별번호, 작업일, 작업명, 부대비용, 진행상태)
- 작업정비항목(작업번호, 정비항목)

### 2NF

복합키의 일부에만 의존하는 속성을 없애야 한다.  
`관리하다`, `처리하다`, `작업정비항목`은 키 전체로 의미가 정해지므로 부분 종속이 없다.

### 3NF

기본키가 아닌 속성이 다른 일반 속성을 결정하면 안 된다.

- `판매일`은 차량보다 판매계약에 가까우므로 판매계약으로 이동한다.
- `보증기간`, `보증항목`은 보증 처리에만 필요하므로 보증처리로 분리한다.

| 고객 | 고객번호, 이름, 주민번호, 연락처, 주소 | PK: 고객번호 |
| 차량 | 차량식별번호, 차량번호, 모델명, 연식, 차량상태, 매입가, 판매가, 매물등록일 | PK: 차량식별번호 |
| 차량작업 | 작업번호, 차량식별번호, 작업일, 작업명, 부대비용, 진행상태 | PK: 작업번호 / FK: 차량식별번호 |
| 작업정비항목 | 작업번호, 정비항목 | PK: 작업번호, 정비항목 / FK: 작업번호 |
| 판매계약 | 계약번호, 계약일, 계약금액, 판매방식, 판매일, 인도완료여부, 인도일, 예약일, 예약상태, 차량식별번호, 고객번호, 직원번호 | PK: 계약번호 / FK: 차량식별번호, 고객번호, 직원번호 |
| 사후처리 | 처리번호, 처리유형, 요청일, 처리일, 처리내용, 처리상태, 차량식별번호, 고객번호 | PK: 처리번호 / FK: 차량식별번호, 고객번호 |
| 보증처리 | 처리번호, 보증기간, 보증항목 | PK: 처리번호 / FK: 처리번호 |
| 관리하다 | 직원번호, 차량식별번호 | PK: 직원번호, 차량식별번호 / FK: 직원번호, 차량식별번호 |
| 처리하다 | 직원번호, 처리번호 | PK: 직원번호, 처리번호 / FK: 직원번호, 처리번호 |

## 4. 정리

3NF까지 정규화하여 작업 정보, 정비항목, 보증 정보를 따로 분리했다.  
그 결과 중복과 불필요한 빈 값을 줄일 수 있다.
