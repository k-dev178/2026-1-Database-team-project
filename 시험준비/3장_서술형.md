# 요구수집 및 분석

## 연습문제

Q1. 요구수집단계의 주요 업무.
사용자가 원하는 DB의 용도를 파악하고, DB가 사용자에게 제공해야할 정보를 결정.
이를 기반으로 `요구수집명세서`를 작성.

+ 추가
- 범기관적 경영 목표 및 `제약조건` 식별
- 기존문서 조사
- 운영환경 파악

Q2. 요구수집 명세서를 작성할 때 포함해야할 항목.
1. 요구수집 내용
2. 정보 제공자
3. 수집 담당자
4. 관련 첨부파일

Q3. 요구분석단계의 주요 업무가 아닌것.
1. 업무 영역 `분할`
2. 상세 업무 `분석`
3. 요구분석명세서 `작성`
4. 요구사항 수용범위 `결정` 
시간이 한정되어 있어서 요구를 모두 들어줄순 없음..

Q4. 요구분석이 어려운 이유.
요구분석은 사용자의 요구가 모호하고 불완전하며, 요구사항이 계속 변경될 수 있기 때문에 어렵다.

암기용:
모호함, 불완전함, 요구변경

Q5. 요구수집을 위한 인터뷰 시 유의 사항.
요구수집 인터뷰 시에는 질문을 사전에 `준비`하고, 사용자의 답변을 왜곡하지 않으며(`경청`), 모호한 요구사항은 추가 질문으로 명확히 `확인`해야 한다. 또한 인터뷰 내용을 `기록`하고 확인받아야 한다.

암기용:
준비 → 경청 → 확인 → 기록

Q6. DB 구축 전체 단계에서 요구 분석 단계가 가장 중요한 이유.
요구 분석이 잘못되면 이후 설계와 구현도 잘못되기 때문에 가장 중요하다.

암기용:
요구 분석이 틀리면 뒤 단계가 전부 틀어진다.

Q7. 요구사항 특징
1. 요구사항은 계속 변화함
2. 요구사항은 점차 확장함.
3. 요구사항은 불완전함(애매모호).
4. 요구사항은 라이프사이클이 있다. (생성 -> 소멸)

암기용:
변화, 확장, 불완전, 라이프사이클
