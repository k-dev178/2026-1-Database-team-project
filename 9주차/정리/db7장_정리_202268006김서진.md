# DB 7장 관계 데이터 모델

## 관계 데이터 모델이란?

DB를 2차원 테이블(=릴레이션) 묶음으로 보는 모델. 1970년에 IBM의 Codd 박사가 처음 제안했음.
겉보기엔 그냥 표인데, 이론적으론 수학의 집합/릴레이션 개념에 기반함.

특징 두 개
- 개체랑 관계 둘 다 표 하나로 표현됨
- ER 모델을 관계 모델로 바꾸기 쉬움 (그래서 8장에서 ERD → 릴레이션 변환을 하는 거)


## 주요 용어란?

표 하나 보면서 용어 매칭하는 게 제일 빠름.

| 용어 | 뜻 |
|---|---|
| 튜플(tuple) | 행 하나. 인스턴스의 단위 |
| 속성(attribute) | 열. 표 맨 위에 컬럼명 적힌 거 |
| 도메인(domain) | 그 속성에 들어갈 수 있는 값의 범위 (타입+조건) |
| 차수(degree) | 속성 개수 (열의 수) |
| 카디널리티(cardinality) | 튜플 개수 (행의 수) |
| 릴레이션 | 표 자체 |
| 릴레이션 스키마 | 표의 구조. 헤더 부분 (속성 이름들) |
| 릴레이션 인스턴스 | 그 시점에 들어있는 실제 튜플들 |
| 키(key) | 튜플을 유일하게 구분하는 속성(들) |

차수랑 카디널리티 헷갈리기 쉬운데
- 차수 = 컬럼 수 (가로)
- 카디널리티 = 행 수 (세로)


## 릴레이션은 어떻게 정의되는가?

수학적으로는 도메인들의 카티션 곱의 부분집합으로 정의함.
즉 `R ⊆ D1 × D2 × ... × Dn`

말로 풀면, 각 속성에 들어갈 수 있는 값들의 모든 조합 중에서 의미 있는 것만 골라낸 게 릴레이션.

릴레이션 스키마는 보통 이렇게 씀

    사원(사번, 이름, 부서번호, 입사일)


## 릴레이션의 특성은 무엇인가?

네 가지. 외워야 됨.

1. 튜플의 유일성 — 같은 튜플이 두 번 들어갈 수 없음 (집합이라서)
2. 튜플의 무순서 — 행의 순서는 의미 없음
3. 속성의 무순서 — 컬럼 순서도 의미 없음
4. 속성의 원자성 — 한 칸에는 더 쪼갤 수 없는 값 하나만. 여러 값이나 복합값 안 됨

원자성 때문에 다중치 속성이나 복합 속성을 그대로 못 넣고, 8장에서 별도 표로 빼거나 컬럼 쪼개는 거.


## 관계 데이터베이스란?

관계 DB = 릴레이션들의 집합.

관계 DB 스키마 = 릴레이션 스키마들 + 무결성 제약조건

관계 DB 인스턴스 = 그 시점의 모든 릴레이션 인스턴스 모음

스키마는 설계도(고정), 인스턴스는 안에 든 데이터(계속 바뀜) 이렇게 보면 됨.


## 키(Key)란?

튜플을 유일하게 식별하기 위한 속성 또는 속성 묶음. 종류 다섯 개.

### 후보키 (Candidate Key)
유일성 + 최소성 둘 다 만족하는 속성 집합.
- 유일성: 튜플마다 값이 다 달라서 구분 가능
- 최소성: 속성 하나라도 빼면 유일성 깨짐 (꼭 필요한 것만 모인 상태)

### 슈퍼키 (Super Key)
유일성만 있는 거. 최소성은 신경 안 씀.
즉 후보키에 쓸데없는 속성 더 붙은 것도 슈퍼키임. 후보키는 슈퍼키 중에서 군더더기 뺀 것.

### 기본키 (Primary Key, PK)
후보키 여러 개 중에 대표로 고른 하나. DB가 실제로 식별에 쓰는 키.
고를 때
- NULL 가질 수 있는 거 피하기
- 값 자주 바뀌는 거 피하기
- 단순한 게 좋음 (예: 학번 > 주민번호)

### 대체키 (Alternate Key)
후보키 중에 기본키로 안 뽑힌 나머지들.

### 외래키 (Foreign Key, FK)
다른 릴레이션의 기본키를 참조하는 속성. 릴레이션끼리 연결시키는 역할.
- 참조하는 쪽이랑 참조되는 쪽 도메인은 같아야 됨
- NULL 가능
- 자기 자신을 참조할 수도 있음 (예: 사원 - 관리자사번)
- 외래키가 기본키의 일부가 되는 경우도 있음 (약한 개체)


## 무결성 제약조건(Integrity Constraint)이란?

DB에 저장된 데이터가 정확하고 일관성 있게 유지되도록 강제하는 조건. 종류 세 개.

### 개체 무결성 (Entity Integrity)
기본키는 NULL이면 안 됨. 중복도 안 됨.
이유: PK가 비어있으면 그 튜플을 식별할 수가 없음.

### 참조 무결성 (Referential Integrity)
외래키 값은 참조하는 릴레이션의 기본키에 실제로 존재하는 값이거나, 아니면 NULL이어야 함.
없는 값을 가리키면 깨진 참조가 되니까.

### 도메인 무결성 (Domain Integrity)
각 속성 값은 정해진 도메인에 맞아야 됨 (타입, 길이, 형식 등).
예) 학년에 100 넣기 안 됨, 휴대폰에 한글 넣기 안 됨.


## 무결성 제약조건은 어떻게 정의하는가?

두 가지 방식이 있음.

- 묵시적 정의 — PK, FK 같은 거 정의하면 DBMS가 알아서 개체/참조 무결성 검사함. 따로 안 짜도 됨.
- 명시적 정의 — NOT NULL, UNIQUE, CHECK, DEFAULT 같은 키워드로 직접 거는 거. 도메인 무결성은 이렇게 명시해야 됨.

명시적 제약 키워드 정리

| 키워드 | 의미 |
|---|---|
| NOT NULL | NULL 못 넣음 |
| UNIQUE | 중복 못 넣음 |
| CHECK | 조건식 만족하는 값만 |
| DEFAULT | 값 안 넣으면 기본값 자동 입력 |


## 꼭 외워야 할 핵심은?

- 릴레이션 4가지 특성: 튜플 유일성, 튜플 무순서, 속성 무순서, 속성 원자성
- 차수 = 열 개수 / 카디널리티 = 행 개수
- 후보키 = 유일성 + 최소성, 슈퍼키 = 유일성만
- 기본키는 NULL 안 됨 (개체 무결성)
- 외래키는 참조하는 PK값 or NULL (참조 무결성)
- 묵시적(PK/FK) vs 명시적(NOT NULL, UNIQUE, CHECK, DEFAULT)
