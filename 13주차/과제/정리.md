# 물리적 설계 정리

## 물리적 설계

- 논리적 설계 결과를 실제 DBMS에 저장·운영할 수 있도록 구체화하는 단계
- 데이터 중심 설계와 처리 중심 설계를 함께 고려함
- 주요 산출물: 내부 스키마, 인덱스 정의서, 뷰 정의서

## 물리적 스키마 모델링

- 릴레이션 스키마와 무결성 제약조건을 바탕으로 내부 스키마를 정의함
- 릴레이션은 테이블, 속성은 칼럼, 관계는 외래키로 표현함
- 테이블명, 칼럼명, 데이터 타입, 크기, NULL 허용 여부, PK/FK/UQ/CHECK 등을 명시함

## 내부 스키마

- DB 내부에 실제로 저장되는 테이블 구조
- 논리적 스키마보다 DBMS 구현에 가까운 형태
- 포함 내용:
  - 테이블명
  - 칼럼명
  - 데이터 타입과 크기
  - 기본키, 외래키, 유일키
  - NOT NULL, CHECK 등 제약조건

## 성능 향상을 위한 물리적 구조 변경

- 테이블 재정의: 역정규화, 테이블 추가, 테이블 분할
- 통계 테이블 추가: 자주 쓰는 집계 데이터를 별도 저장
- 부분 테이블 추가: 자주 쓰는 일부 데이터만 별도 저장
- 이력 테이블 추가: 변경 이력이나 진행 이력을 별도 저장
- 수직 분할: 칼럼 기준으로 테이블 분리
- 수평 분할: 행 기준으로 테이블 분리
- 동일 칼럼 추가: 자주 조회하는 칼럼을 중복 저장
- 파생 칼럼 추가: 합계, 평균, 개수 등 계산 결과를 저장

## 수직 분할이 필요한 경우

- 검색 위주 칼럼과 갱신 위주 칼럼이 구분되는 경우
- 특정 칼럼이 매우 자주 검색되는 경우
- 특정 칼럼의 크기가 큰 경우
- 특정 칼럼에 보안이 필요한 경우

## 수평 분할 시 유의점

- 데이터가 많고 특정 행 그룹만 자주 접근할 때 사용함
- 분할 테이블을 다른 디스크에 두면 입출력 효율을 높일 수 있음
- DBMS의 파티셔닝 기능을 활용할 수 있음

## 인덱스

- 테이블 행에 빠르게 접근하기 위한 별도 저장 구조
- 칼럼 값과 행의 논리적 주소로 구성됨
- PK와 UNIQUE 제약조건은 DBMS가 자동으로 인덱스를 생성함
- 사용자는 `CREATE INDEX`로 필요한 칼럼에 인덱스를 직접 생성할 수 있음
- 인덱스가 많으면 검색은 빨라질 수 있지만 INSERT, DELETE, UPDATE 성능은 떨어질 수 있음

## 인덱스 대상 선정 기준

- WHERE, ORDER BY, GROUP BY, DISTINCT, JOIN 조건에 자주 사용되는 칼럼
- 분포도가 좋은 칼럼
- 평균 분포도가 대략 10% 미만인 칼럼
- 여러 칼럼이 함께 자주 사용되면 결합 인덱스 고려

```text
분포도(%) = 1 / 칼럼 값의 종류 * 100
분포도(%) = 특정 값을 갖는 평균 행 수 / 전체 행 수 * 100
```

## 인덱스가 적합한 경우

- 테이블 크기가 큰 경우
- 조건 검색에 자주 사용되는 경우
- 칼럼 값의 종류가 다양한 경우
- 전체 행 중 적은 부분만 조회하는 경우
- 둘 이상의 칼럼이 조건이나 조인에 함께 자주 사용되는 경우

## 인덱스가 부적합한 경우

- 테이블 크기가 작은 경우
- 조건 검색에 거의 사용되지 않는 경우
- 테이블 갱신이 자주 발생하는 경우
- 대부분의 질의가 전체 행의 많은 부분을 조회하는 경우

## 인덱스 최적화

- 자주 수정되는 칼럼에는 인덱스를 피함
- 한 테이블의 인덱스가 너무 많으면 DML 성능이 저하됨
- 날짜 단위 처리만 필요하면 DATE 대신 `CHAR(8)` 형식도 검토 가능
- 결합 인덱스는 검색 범위를 많이 줄이는 칼럼을 앞에 둠
- 정렬 방향이 중요하면 ASC/DESC를 함께 검토함

## 뷰

- 하나 이상의 테이블에서 유도된 논리적 테이블
- 실제 데이터를 저장하지 않고 뷰 정의만 저장함
- 복잡한 테이블 구조를 단순하게 보여줄 수 있음
- 보안, 검색 편의성, 데이터 독립성 향상에 유용함
- 기본 테이블이 삭제되면 관련 뷰도 영향을 받음
- 뷰 변경은 ALTER가 아니라 삭제 후 재생성 방식으로 처리함

## 뷰의 장점

- 특정 데이터만 보여줄 수 있어 보안 관리가 쉬움
- 복잡한 조인을 단순화할 수 있음
- 기본 테이블 구조 변경의 영향을 줄일 수 있음
- 사용자 그룹별로 다른 화면을 제공할 수 있음

## 뷰의 단점

- 뷰 정의 자체를 직접 갱신하기 어려움
- 삽입, 삭제, 갱신 연산에 제한이 있음
- 복합 뷰는 DML 사용에 특히 주의해야 함

## 뷰 종류

- 단순 뷰: 하나의 테이블을 기반으로 생성
- 복합 뷰: 여러 테이블, 그룹 함수, 그룹핑 등을 기반으로 생성
