## 3. 요구 분석

### 3-1. 기능 요구사항 (꼭 있어야 하는 기능)

| 번호 | 요구사항 | 쉬운 설명 |
|------|---------|----------|
| F-01 | 차량 상태 관리 | 차가 지금 "창고에 있는지 / 고치는 중인지 / 팔리는 중인지" 표시 |
| F-02 | 차량 검색 | 차 번호, 모델명, 연식, 가격 등으로 원하는 차를 바로 검색 |
| F-03 | 가격 및 수익 관리 | 얼마에 사왔고(매입가), 얼마에 팔았는지(판매가), 얼마 남았는지(수익) 계산 |
| F-04 | 부대비용 기록 | 정비비·세차비·탁송비 같은 추가 비용도 함께 기록 |
| F-05 | 고객 정보 관리 | 고객 연락처, 관심 차량, 상담 내용 저장 |
| F-06 | 판매 이력 조회 | 판매 완료 후에도 "누가 언제 얼마에 샀는지" 다시 확인 가능 |
| F-07 | 차량 옵션 관리 | 네비게이션, 후방카메라, 선루프 등 옵션 정보 기록 |
| F-08 | 판매 통계 | 월별 판매량, 차종별 판매량, 평균 판매가 등 통계 확인 |
| F-09 | 담당자 지정 | 차량마다 담당 직원이 누구인지 표시 |
| F-10 | 재고 현황 파악 | 오래 안 팔리는 차를 한눈에 확인 |
| F-11 | 상태 자동 변경 | 차량 판매 시 재고 목록에서 자동으로 "판매완료"로 상태 변경 |

## 4. 개체(Entity) · 속성(Attribute) · 관계(Relationship) 설계

> **개체** = 데이터베이스에 저장할 "대상"
> **속성** = 그 대상이 가진 "정보 항목"
> **관계** = 개체끼리 어떻게 연결되는지

---

### 개체 1 — 차량 (Vehicle)

> "우리 가게에 있는 중고차 한 대 한 대"

| 속성 | 설명 | 예시 |
|------|------|------|
| 차량ID *(기본키)* | 차량을 구별하는 고유 번호 | V001 |

## 5. 관계 정리

```
차량 ──────────── 부대비용
 │  (1개 차량에 여러 비용 발생)
 │
 ├──────────────── 차량옵션
 │  (1개 차량에 여러 옵션 존재)
 │
 └──────────────── 판매이력
                    │
          ┌─────────┴──────────┐
        고객                  직원
  (여러 차량 구매 가능)   (여러 판매 담당 가능)
```

| 관계 | 설명 | 형태 |
|------|------|------|
| 차량 → 부대비용 | 차 1대에 비용이 여러 건 생길 수 있음 | 1 : 多 |
| 차량 → 차량옵션 | 차 1대에 옵션이 여러 개일 수 있음 | 1 : 多 |
| 차량 → 판매이력 | 차 1대는 딱 1번 팔림 | 1 : 1 |
| 고객 → 판매이력 | 고객 1명이 여러 번 살 수 있음 | 1 : 多 |
| 직원 → 판매이력 | 직원 1명이 여러 건 담당할 수 있음 | 1 : 多 |
