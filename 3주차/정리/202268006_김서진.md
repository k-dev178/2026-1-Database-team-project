# 데이터베이스 3주차 정리

---

## 1. DBMS란?

> **DBMS = DB를 관리해주는 소프트웨어**

- DB에 저장된 데이터를 혼자 쓰는 게 아니라 **여러 사람이 함께** 사용할 수 있게 해주는 프로그램
- 모든 데이터 접근은 반드시 DBMS를 통해서만 가능

```
사용자/프로그램 → DBMS → DB
```

> **DB vs DBMS vs DBS**
> - **DB**: 데이터 저장소
> - **DBMS**: DB를 관리하는 소프트웨어
> - **DBS(데이터베이스 시스템)**: DB + DBMS + 사용자 + 언어 등을 모두 포함한 전체 시스템

---

## 2. DBMS의 3가지 필수 기능

| 기능 | 설명 | 비유 |
|------|------|------|
| **정의(Definition)** | 데이터의 형태·구조를 설정 | 서랍 만들기 |
| **조작(Manipulation)** | 검색·삽입·삭제·갱신 | 서랍에 넣고 빼기 |
| **제어(Control)** | 정확성·보안·동시성 유지 | 서랍에 자물쇠 |

### 제어 기능의 3가지 요건
- **무결성**: 데이터가 항상 올바른 값이어야 함
- **보안**: 권한 있는 사람만 접근 가능
- **동시성 제어**: 여러 사람이 동시에 써도 충돌 없게

---

## 3. DBMS 구성 요소

```
사용자 요청 → 해석 → 스키마 거침 → 저장된 데이터 접근 → 실행
```

| 구성 요소 | 하는 일 |
|-----------|---------|
| **DDL 컴파일러** | 스키마(DB 설계도)를 내부 형태로 변환 → 시스템 카탈로그에 저장 |
| **DML 예비 컴파일러** | 프로그램 안에 끼워진 DB 명령문을 꺼냄 |
| **DML 컴파일러** | DB 명령문을 컴퓨터가 실행 가능한 코드로 변환 |
| **질의어 처리기** | 일반 사용자가 입력한 SQL 등 질의문 처리 |
| **트랜잭션 관리자** | 무결성 검사 + 권한 검사 + 동시성 제어 + 복구 |
| **런타임 DB 처리기** | 실제 DB 연산(검색, 갱신 등) 실행 |
| **저장 데이터 관리자** | 디스크의 실제 데이터에 접근 |

---

## 4. 데이터베이스 사용자

| 종류 | 설명 | 주로 쓰는 언어 |
|------|------|----------------|
| **DB 관리자 (DBA)** | DB 설계·구축·관리 총괄. 안전하게 유지하는 책임자 | DDL, DCL |
| **일반 사용자** | DB 전문지식 없이 검색/삽입/삭제 등 사용 | 질의어(SQL) |
| **응용 프로그래머** | 일반 사용자용 프로그램 개발하는 전문가 | DML, 호스트 언어 |

---

## 5. 데이터가 속한 세계

현실 세계의 데이터가 DB에 저장되기까지 3단계를 거침

```
현실 세계 → 개념 세계 → 컴퓨터 세계
  (실체)    (개체 타입)   (레코드 타입)
```

| 세계 | 단위 | 구성 | 예시 |
|------|------|------|------|
| 현실 세계 | 개체(Entity) | 특성(feature) | 실제 학생 한 명 |
| 개념 세계 | 개체 타입 | 속성(Attribute) | 학생(학번, 이름, 전공) |
| 컴퓨터 세계 | 레코드 타입 | 필드(Field) | student(id: 숫자10, name: 문자20) |

> 같은 사람도 **어떤 세계(맥락)냐에 따라** 필요한 속성이 달라짐
> - 대학 세계 → 학번, 전공, 평점
> - 쇼핑몰 세계 → id, 배송지, 구매목록

---

## 6. 데이터 모델링 3단계

> **데이터 모델링** = 현실 세계 데이터를 DB에 저장할 수 있게 변환하는 과정

```
현실 세계
   ↓ 개념적 모델링 (ER 다이어그램)
개념적 구조 (추상적)
   ↓ 논리적 모델링
논리적 구조 (데이터 모델, 예: 릴레이션)
   ↓ 물리적 모델링
물리적 구조 (실제 디스크에 저장)
```

| 단계 | 도구 | 결과물 |
|------|------|--------|
| 개념적 모델링 | ER 모델 | ER 다이어그램 |
| 논리적 모델링 | 관계 데이터 모델 등 | 릴레이션 스키마 |
| 물리적 모델링 | 인덱스, 레코드 형식 등 | 저장 DB |

---

## 7. 데이터 모델 (Data Model)

> **데이터 모델 = DB 안의 데이터를 표현하는 개념적 도구**

### 구성: DM = \<S, O, C\>

| 요소 | 이름 | 설명 |
|------|------|------|
| **S** | 데이터 구조 | 무엇을 저장할지 (정적) |
| **O** | 연산 | 어떻게 조작할지 (동적) |
| **C** | 제약조건 | 어떤 값이 허용되는지 |

### 종류

| 종류 | 설명 |
|------|------|
| **개념적 데이터 모델** | 사람이 이해하기 위한 추상적 모델 (예: ER 모델) |
| **논리적 데이터 모델** | DBMS가 이해할 수 있는 모델 (예: 관계형, 계층형, 네트워크형) |

---

## 8. DB 구축 6단계

```
1. 요구 수집 및 분석
2. 개념적 설계
3. DBMS 선정
4. 논리적 설계
5. 물리적 설계
6. 구현 및 테스트
```

| 단계 | 주요 업무 |
|------|-----------|
| **요구 수집·분석** | 사용자 인터뷰, 설문 → 요구 분석 명세서 작성 |
| **개념적 설계** | ER 다이어그램 작성 |
| **DBMS 선정** | 논리적 모델, 운영 환경, 비용 고려 |
| **논리적 설계** | 릴레이션 스키마 + 무결성 제약조건 정의 |
| **물리적 설계** | 인덱스, 뷰 등 정의 |
| **구현·테스트** | DB 생성, 초기 데이터 삽입, 앱 개발 및 테스트 |

### DB 설계 시 고려사항

| 항목 | 의미 |
|------|------|
| 무결성 | 데이터 값이 항상 제약조건 만족 |
| 일관성 | 데이터 간 모순 없음 |
| 복구 | 장애 발생 시 복원 가능 |
| 보안 | 불법 접근 차단 |
| 효율성 | 응답 시간 단축, 저장 공간 최적화 |
| 확장성 | 새 데이터·앱 추가해도 시스템에 영향 없음 |

## 9. 요구 수집 및 분석

### 요구 수집 방법
- **직접**: 인터뷰, 회의
- **간접**: 설문조사, 기존 문서 조사

### 인터뷰 질문 유형
| 유형 | 설명 | 예시 |
|------|------|------|
| **닫힌 질문** | 예/아니요, 단답형 | "이 기능이 필요합니까?" |
| **열린 질문** | 자유롭게 서술 | "가장 불편한 기능은?" |
| **추가 질문** | 앞 답변에 대한 보충 질문 | "왜 불편하다고 느끼나요?" |

### 요구 분석 명세서 작성 유의사항
- 단순하고 명확한 문체 사용
- 애매모호한 표현 금지
- 주어·목적어·서술어 명확히
- 용어 사전 만들어 일관성 유지

### 트랜잭션 요구 분석 명세서
- 업무별로 필요한 **데이터 조작 작업** (검색·삽입·삭제·변경)을 문서화
- 작업 주체(누가 하는지)를 명확히 작성

## 10. 사례 요약

### 온라인 쇼핑몰 DB
- **업무 영역**: 상품관리 / 구매처 관리 / 고객관리 / 판매관리
- 핵심 규칙: 실명 인증 회원만 구매 가능, 배송지 최대 3개, 10개 이상 주문 시 5% 할인

### 문화센터 DB
- **업무 영역**: 회원 관리 / 강사 관리 / 강좌 관리 / 수강관리
- 핵심 규칙: 입회비 1만원, 강사 등급(A/B/C), 출석률 80% 이상 시 수료
