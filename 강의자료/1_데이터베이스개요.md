# 학습목표
1. 데이터베이스 정의에 함축된 네 가지 의미를 설명할 수 있다.
2. 데이터베이스의 특징 다섯 가지를 나열할 수 있다.
3. 3단계 데이터베이스 구조를 설명할 수 있다.
4. 논리적 데이터 독립성과 물리적 데이터 독립성을 구분해서 설명할 수 있다.

# 데이터베이스의 정의 (* 데이터베이스 정의에 함축된 네 가지 의미를 설명할 수 있다.)
- 공용 데이터(shared data)
데이터베이스는 여러 응용프로그램이 공동으로 사용하는 데이터이다. 즉, 여러 사용자가 다른목적으로 공유하는 데이터다.

- 통합 데이터(integrated data)
데이터베이스는 한곳에서 통합해서 관리한다. 이 관리중 하나가 데이터 중복을 최소화해서 저장공간을 절약하는 것이다. 하지만 검색 및 처리의 효율성을 위해 중복해서 넣는 경우가 있는데 이것을 최소한의 중복(minimal redundancy)이라고 부른다.

그리고 이 중복된 데이터는 관리자가 미리 파악하여 관리할 수 있으므로 통제된 중복(controlled redundancy)이라고 부른다.

- 저장 데이터(stored data)
데이터베이스는 컴퓨터가 직접 접근할 수 있는 저장장치에 저장됨.<br>
직접호출이 가능.

- 운영 데이터(operational data)
데이터베이스는 조직의 고유한 기능을 수행하기 위한 필수 데이터만 저장한다.<br>
따라서 일시적으로 필요한 임시데이터는 운영데이터에 해당하지 않으므로 저장하지 않는다.

# 데이터베이스의 특징 (* 데이터베이스의 특징 다섯 가지를 나열할 수 있다.)
- 동시 공용(concurrent sharing)
데이터베이스는 한곳에 저장하고 여러 응용프로그램이나 사용자가 접근을 하기 때문에, 같은 데이터를 동시에 사용하는 경우가 많다.

- 지속적인 변화(continuous evolution)
데이터베이스는 동적이다. 끊임 없이 변하는 현실세계를 반영해야하기 때문에 삽입, 삭제, 갱신에 의해 현재 데이터를 정확히 유지해야한다.

- 실시간 접근성(real-time accessibility)
데이터베이스는 사용자에의해 언제나 접근이 가능해야한다.

- 내용에 의한 참조(contents reference)
데이터베이스는 주소나 위치가 아닌, 데이터의 내용에 의해 참조 된다.

예) "총무과의 근무하는 모든 사원을 검색하시오"
이러면 총무과의 사원들이 모두 검색됨.

- 데이터베이스 관리 시스템(DBMS)에 의한 관리
데이터베이스를 효율적으로 구축하고 관리하기 위해서는 DBMS라는 전용 소프트웨어가 필요하다.
대표적으로 MySQL과 오라클, MS-SQL등이 있다.

# 3단계 데이터베이스 구조 (* 3단계 데이터베이스 구조를 설명할 수 있다.)
## 외부단계와 외부스키마
외부단계는 DB에대한 각 사용자의 관점이다.
각 사용자가 생각하는 개인적인 DB 구조를 정의한다.

외부 단계에서 사용자가 필요로 하는 DB 구조를 정의한 것을 외부 스키마라고 한다. (서브스키마라고도 함.)

## 개념단계와 개념스키마
이 단계에서는 조직전체의 관점으로, 조직전체를 위한 DB의 **논리적 구조**를 정의한다.

개념스키마에서는 개체와 관계, 제약조건, DB의 접근권한과 무결성 규칙, 보안정책의 관한 명세도 포함한다.
개념스키마를 단순히 스키마라고 부르기도 한다.

## 내부단계와 내부스키마
내부단계에서는 저장장치의 관점(view)으로, DB에 어떤 데이터를 어떻게 저장할것 인지를 정의한다.
따라서 저장될 내부 레코드의 형식이나 인덱스 유무, 저장 데이터 항복의 데이터 타입과 크기 등을 포함한다.

내부스키마는 내부 단계에서 개념 스키마의 저장구조를 정의한것이다. (개념스키마와 마찬가지로 1개만 존재.)


# 데이터 독립성 (* 논리적 데이터 독립성과 물리적 데이터 독립성을 구분해서 설명할 수 있다.)
데이터 독립성이랑 **논리적 데이터 구조**나 **물리적 데이터 구조**가 변경되어도 응용 프로그램에 영향을 주지 않는 성질을 말한다.

## 논리적 데이터 독립성
응용 프로그램에 영향을 주지 않고 DB의 논리적 구조, 즉 개념 스키마를 변경할 수 있는 것을 의미한다.

## 물리적 데이터 독립성
응용 프로그램과 DB의 논리적 구조에 영향을 주지 않고 물리적 구조, 즉 파일 편성과 데이터 액세스 방법 등을 변경 할 수 있는 것을 의미한다.
