# 학습 목표
1. 요구 수집 단계의 주요 업무를 설명할 수 있다.
2. 요구 분석 단계의 주요 업무를 설명할 수 있다.
3. 데이터 요구 분석 명세서 작성 시 유의 사항을 설명할 수 있다.
4. 데이터 요구 분석 명세서를 작성할 수 있다.
5. 트랜잭션 요구 분석 명세서를 작성할 수 있다.

# 요구 수집 및 분석 개요
![alt text](<기본 폴더 - 9.jpg>)

1. 사용자 그룹 및 담장자 식별
DB를 사용할 사용자 그룹과 요구 수집 및 분석에 참여할 업무 담당자를 식별한다.

2(a). 사용자 요구사항 수집
주요 사용자 및 업무 담당자와의 대화, 인터뷰, 회의와 같은 직접적인 방법이나 온/오프라인 설문조사와 같은 간접적인 방법을 활용해서 DB의 용도를 파악하고 전반적인 요구사항을 수집한다.

2(b). 범기관적 제약조건 파악
DB를 사용할 기관의 경영 정책이나 규정, 조직관리, 기획 정보 등을 파악해서 요구사하에 어떻게 반영할지 결정한다.

2(c). 기존 문서 조사
기존 응용 프로그램과 관련된 매뉴얼, 각종 양식, 보고서, 차트 등 기존 문서를 조사한다.

3. 요구 수집 명세서 작성
직*간접적인 방법으로 수집한 사용자 요구사항과 범기관적 제약조건, 기존 문서 조사 결과 등을 체계적으로 정리하고 요약한다.

4(a). 업무 영역 분할
요구 수집 결과를 기초로 하여 전체 업무를 상세 업무 분석의 기본 단위가 되는 소단위의 업무 영역으로 분할하고, 업무 영역 분할도를 작성한다.

4(b). 상세 업무 분석
요구 수집 결과를 기초로 하여 분할한 업무 영역별로 요구되는 데이터 및 트랜잭션을 상세히 분석한다.

5. 요구 분석 명세서 작성
상세 업무 분석 결과를 기초로 하여 업무별로 요구되는 데이터 요구 분석 명세서와 트랜잭션 요구 분석 명세서를 각각 작성한다.

6. 수용 범위 결정
개념적 설계 단계로 넘어가기 전에 요구 분석된 내용 가운데 DB 구축에 포함할 수용 범위를 결정한다.

# 데이터 요구 분석 명세서 작성시 유의 사항.
1. 단순한 표준 문체를 사용한다.
구어체 x

2. 애매모호한 표현을 피하도록 한다.
"교무처에서 수강신청 업무를 담당한다" -> "교무처 학사팀의 수업지원 담당자가 수강신청 업무를 담당한다."

3. 추상화 수준에 맞는 적절한 표현을 사용한다.
"천안", 서울 x
상세주소전체 x
"쌍용2동", "종로2가" o

4. 지나치게 전문적인 용어보다 일반적인 용어를 사용한다.
5. 용어 간의 참조가 명확하도록 작성한다.
6. 가능하면 주어, 목정어, 서술어(동사)가 분명하도록 작성한다.
7. 이음동의어와 동음이의어의 표현을 점검한다.
8. DB 구축 프로젝트와 관련된 용어 사전 또는 자료 사전을 만들어서 사용한다.
