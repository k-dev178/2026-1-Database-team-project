# 7장 관계 데이터 모델

## 1. 관계 데이터 모델 개요

**관계 데이터 모델**은 데이터베이스(DB)를 **2차원 표(테이블)** 들의 모음으로 정리하는 방법이다.
- 1970년에 IBM의 코드(Codd) 박사가 처음 제안했다.
- 이런 표를 "릴레이션(relation)"이라고 부른다.
- 표의 **행(가로줄)** 은 한 사람/물건의 정보, **열(세로줄)** 은 항목 이름이다.

**특징**
- 모든 것(개체와 관계)이 2차원 표로 표현된다.
- ER 모델을 관계 데이터 모델로 바꾸기가 쉽다.

**릴레이션과 그냥 테이블의 차이**
- 릴레이션은 추상적인 개념, 테이블은 그걸 그림으로 그린 것이다.
- 하나의 릴레이션은 여러 모양의 테이블로 그릴 수 있다.
- 테이블은 똑같은 줄을 허락하지만, **릴레이션은 똑같은 줄을 허락하지 않는다** (수학의 집합 개념).

## 2. 주요 용어

| 용어 | 뜻 |
|---|---|
| 투플(tuple) | 각 행(가로줄). 한 사람/물건의 정보 한 줄. |
| 속성(attribute) | 각 열(세로줄). 정보의 가장 작은 단위. |
| 도메인(domain) | 한 속성이 가질 수 있는 모든 값의 집합. |
| 가수(cardinality) | 투플(행)의 개수. |
| 차수(degree) | 속성(열)의 개수. |
| 릴레이션 스키마 | 속성들의 집합 (표의 머리 부분). |
| 릴레이션 인스턴스 | 투플들의 집합 (표의 내용 부분). |
| 릴레이션 | 스키마 + 인스턴스 |
| 키(key) | 투플을 유일하게 구별하는 속성(들). |

> 릴레이션 = 릴레이션 스키마 + 릴레이션 인스턴스

## 3. 릴레이션의 특성

- **투플의 유일성**: 똑같은 행은 있을 수 없다.
- **투플의 무순서성**: 행의 순서는 의미 없다.
- **속성의 무순서성**: 열의 순서도 의미 없다.
- **속성의 유일성**: 한 릴레이션 안에 같은 이름의 속성은 없다.
- **속성의 원자성**: 한 칸에는 더 이상 쪼갤 수 없는 값 하나만 들어간다. (널 값도 원자 값으로 본다.)

## 4. 관계 데이터베이스 (관계 DB)

**관계 DB 스키마 = 릴레이션 스키마들 + 무결성 제약조건**

- 관계 DB는 여러 릴레이션의 모음이다.
- 릴레이션끼리 서로 관련을 가질 수 있다.
- 사용자에게는 2차원 표로 보여주지만, 실제 저장 방식은 다르다.

## 5. 데이터베이스 키

| 키 종류 | 설명 |
|---|---|
| **후보키(candidate key)** | 유일성 + 최소성을 모두 만족하는 속성(들). |
| **슈퍼키(super key)** | 유일성은 만족, 최소성은 만족 안 함. |
| **기본키(primary key)** | 후보키 중 하나를 골라 대표로 정한 키. 널 값 X, 중복 X. |
| **복합키(composite key)** | 2개 이상의 속성을 묶어서 만든 기본키. |
| **대체키(alternative key)** | 기본키로 안 뽑힌 나머지 후보키들. |
| **외래키(foreign key)** | 다른 릴레이션의 기본키를 가리키는 키. 릴레이션끼리 연결할 때 쓴다. |

**유일성**: 키 값으로 각 행을 딱 하나로 찾을 수 있어야 한다.
**최소성**: 행을 구별하는 데 꼭 필요한 속성만 있어야 한다.

**외래키 특징**
- 외래키 값은 가리키는 릴레이션의 기본키 값 중 하나거나 널이어야 한다.
- 같은 릴레이션의 기본키도 가리킬 수 있다 (예: 사원이 자기 관리자를 가리킬 때).
- 외래키가 기본키의 일부가 되면 널 값을 가질 수 없다.

## 6. 무결성 제약조건

데이터가 **정확하고 일관성 있게** 유지되도록 DB가 항상 지켜야 하는 규칙이다.

### 종류
- **개체 무결성**: 기본키는 널 값이면 안 된다.
- **참조 무결성**: 외래키는 가리키는 릴레이션의 기본키 값이거나 널이어야 한다.
- **도메인 무결성**: 속성 값은 정해진 도메인 안의 값이어야 한다.

### 정의 방법
- **묵시적 정의**: 기본키/외래키/데이터 타입을 정해두면 자동으로 적용된다.
- **명시적 정의**: 직접 써서 정해야 하는 것들.
  - `NOT NULL`: 널 값 금지
  - `UNIQUE`: 값이 중복되면 안 됨
  - `DEFAULT`: 값이 없을 때 자동으로 들어갈 기본값
  - `CHECK`: 특정 조건을 만족해야 함 (예: 호봉은 10~30 사이)

> DB가 바뀔 때마다 DBMS가 자동으로 검사하므로, 따로 프로그램을 만들 필요가 없다.
